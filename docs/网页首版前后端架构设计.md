# BabyCare Agent 网页首版前后端架构设计

项目负责人已通过架构审查，并选定阿里云百炼。网页首版将总体方案第 10 章 V1.0 的知识问答、V1.1 的会话条件和 V1.2 的门店商品工具组合到一个交付里，同时提前落实 V1.4 的基础权限与安全分流。第 12.3 节给出实施顺序。本次交付范围和通过条件以[已通过的 13 条验收标准](网页首版验收标准.md)为准。前端负责交互与呈现，Java 服务掌握身份、筛选条件、工具执行和证据，语言模型负责理解自然语言与选择证据。

## 代码组织与运行方式

仓库的 Maven 工程声明 Java 21、Spring Boot 4.2.0，当前只有启动类、基础依赖和上下文加载测试。建议沿用项目配置，开发时增加 Web、Security 和相应测试支持。前端采用 HTML、CSS 和原生 JavaScript 模块，由同一应用提供页面和 API。两个页面即可完成首版操作，开发机只需管理一个应用进程和一个可用的模型端点。

| 拟放置的位置 | 职责 |
|---|---|
| `src/main/resources/static/` | 登录页、导购工作台及样式。按登录、请求、对话和结果渲染拆分 JS 模块。 |
| `src/main/java/com/yu/babycare/auth/` | 测试账号、登录会话、当前导购及门店身份。 |
| `…/conversation/` | 对话接口、归属校验、当前选购条件、轮次提交与并发控制。 |
| `…/agent/` | 风险检查、意图与条件变更解析、受控工具调度、答案组装及模型适配。 |
| `…/catalog/` | 门店授权检查、商品与报价查询、硬条件过滤、商品比较、库存服务失败状态。 |
| `…/knowledge/` | 资料加载、审核范围过滤、检索、证据与引用解析。 |
| `src/test/` | 条件合并与筛选测试、带身份的 HTTP 集成测试、模型证据捕获和库存故障替身。 |

从[现有样本目录](../fixtures/)加载同一份商品、价格库存及知识测试资料。开发启动可配置该目录，发布演示包时随包附带，启动时检查 SKU 唯一性、门店关联、金额及数量。后续接公司接口时更换商品与门店报价的数据适配器，网页和对话协议继续使用相同的结果结构。

## 网页与接口

登录成功后工作台显示当前门店、会话消息和输入框。商品结果用可浏览完整集合的列表或比较表显示规格、单包价、库存、来源、快照日期和本次查询时间。知识答案旁展示来源标题、摘要版本及原文入口。澄清、权限不足、工具失败和风险分流使用各自的提示；切换账号时清空页面中的上一个工作台。动态文本按纯文本渲染，来源链接取自服务端校验过的资料元数据。

| 请求 | 输入及输出 |
|---|---|
| `GET /api/session` | 初始化会话与 CSRF 令牌；已登录时返回当前导购与绑定门店，未登录时仅返回登录状态及令牌。 |
| `POST /api/session/login`、`POST /api/session/logout` | 登录验证账号密码并更新会话标识；退出使会话失效。浏览器使用同源会话 Cookie，写请求携带 CSRF 令牌，登录后重新获取令牌。 |
| `POST /api/conversations` | 依据登录身份创建对话，返回对话 ID 和初始版本。 |
| `POST /api/conversations/{id}/messages` | 提交 `text`、客户端生成的 `messageId` 和上次的 `version`；返回新版本、回复类型、文本以及适用的商品、引用或提示。 |
| `GET /api/conversations/{id}` | 读取本人当前门店的对话状态和已提交轮次。刷新或请求超时时据此恢复。 |
| `GET /api/stores/{storeId}/offers/{skuId}` | 在当前导购权限下查询指定门店报价，商品工具复用同一授权与查询服务。用于核对 AC-02、AC-03。 |

未登录访问受限资源返回 401，直接跨店报价请求返回 403。自然语言提出跨店查询时，消息接口返回本轮已处理及 `access_denied` 提示。访问他人的对话统一返回 404。返回商品行包含 SKU、品牌、规格、片数、金额、库存状态、可确认数量、来源、快照日期和查询时间；缺失值保持为空。界面将零库存、查询失败、尚未查询分别呈现。

## 一轮对话如何执行

1. 服务端从会话读取账号与门店，校验对话归属。每轮先检查当前输入的风险，命中高风险就直接返回固定安全提示，该轮停止商品调用和推荐。模型解析阶段若发现额外风险，也走同一分支。
2. 模型适配器接收当前问题、必要上下文和允许使用的工具描述，输出结构化意图、条件变更及工具请求。Java 校验参数和工具名称，拒绝跨店请求。只浏览商品时允许缺尺码，要求具体尺码推荐时先追问。对未提供尺码对照表的商品，不能根据宝宝月龄自行换算尺码。
3. 服务端按字段合并条件。未提及的条件保留，“改成”覆盖原值，“排除”加入排除集合，只有明确撤销才解除。门店取自登录身份。会话按用户和门店隔离，状态包含品类、尺码、预算上限、库存要求、品牌条件及当前候选引用。
4. 商品查询先校验访问范围，再按门店取得报价、执行过滤。预算以人民币单包价作含上限比较，有货指可售包数大于零。所有依赖数据查询成功且结果为空时才产生“无匹配”。库存超时返回“暂无法确认”；下一轮重新查库存，不复用旧数量。比较字段缺失时逐项标注，其他已知字段照常展示。
5. 知识查询先按使用环境、审核状态及资料适用范围筛选，再按标题、关键词与段落检索。两份样本采用显式资料清单登记版本和状态，未知状态默认排除。送给模型的证据包含片段 ID、文本和出处；无合格证据时直接提示资料不足。引用只能解析到本轮返回的片段。涉及金额、库存和规格的陈述由 Java 按结构化结果生成，模型可选择已核实的理由，页面直接渲染对应值。
6. 同一对话一次只处理一个新轮次。按对话 ID 和消息 ID 识别重试，已完成的同一请求返回既有结果；不同消息使用过期版本时返回冲突并引导前端重新读取。成功后一起提交条件、回复和版本。模型超时或返回不可解析内容时提示重试，保留上一轮已确认状态。商品工具失败属于已知业务结果，可提交带失败提示的轮次。

首版建议将导购会话及近期轮次保存在服务端内存，设定失效时间并在退出后清理。页面刷新可恢复当前会话；应用重启后重新登录并开始新对话。库存故障模拟仅在测试配置中启用，使 AC-10 能用相同网页和账号复测。

## 模型与数据接入

Java 适配器通过百炼兼容 Chat 接口调用模型，默认使用北京地域的 qwen-plus。密钥由后端进程的 DASHSCOPE_API_KEY 提供。模型解析结构化意图、选择经过审核的证据，Java 组装可核对的回复。每轮最多两次模型请求，各设 45 秒超时。自动化集成测试使用确定性模型替身，浏览器验收使用百炼端点。

当前两份知识样本适合用小规模文本检索起步。知识模块向上返回带出处的片段，日后扩充到向量检索时能复用同一接口和审核过滤。库存和价格始终通过门店报价服务获取。快照日期来自样本，查询时间来自服务端时钟。

## 验收与观测

| 用例 | 主要验证位置 | 可复核证据 |
|---|---|---|
| AC-01、02、03 | 登录、门店授权、报价服务 | 浏览器账号切换；集成测试检查跨店请求返回 403、无受限报价，两个账号读取各自的门店值。 |
| AC-04、05、06、07 | 工作台、会话条件合并、候选筛选 | 在一个真实模型会话中逐轮输入，核对尺码追问、四款候选、唯一匹配和无匹配；验证筛选时使用的门店与条件。 |
| AC-08、09 | 价格比较、商品字段呈现 | 固定数据测试覆盖恰好 150 元、排除超预算商品，以及缺少透气性资料时的逐项比较。 |
| AC-10 | 库存适配器、回复状态及界面 | 切换测试库存适配器的失败状态，网页显示暂无法确认；恢复后重新提问得到 3 包。 |
| AC-11、12 | 检索过滤、模型请求边界及引用组件 | 浏览器核对原文与版本；集成测试捕获实际提交给模型适配器的证据 ID，验证待审核文档从未出现，无证据时跳过答案生成。 |
| AC-13 | 风险检查与对话调度 | 在商品会话中插入验收用例的高风险描述，检查安全提示、当轮商品调用数为零、回复内没有商品卡片。 |

每轮记录请求 ID、门店、结果类型、工具状态、延迟及证据 ID，便于把网页结果与集成证据对应。常规日志避免保存对话原文、密码或模型密钥。

## 架构审查事项

- **运行基线**：建议沿用 POM 的 Java 21 和 Spring Boot 4.2.0。当前 PowerShell 的 Java 为 1.8，开发前要指定可用的 JDK 21，并通过 Maven Wrapper 验证构建与新增依赖。
- **首次交付取舍**：单应用同源部署、服务端内存会话、文件数据和小规模文本检索。它们分别影响启动方式、重启后的用户体验和日后扩容的替换位置。
- **模型验证**：使用百炼验证多轮条件、商品比较和知识证据选择。密钥仅供服务端使用。
